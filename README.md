# ProSellerOS

**One Platform. Every Marketplace.**

ProSellerOS is a commerce operating system that unifies every online marketplace
(Amazon, Flipkart, Meesho, Myntra, Shopify, WooCommerce, eBay, and more) together
with your own storefronts into a single intelligent dashboard.

This repository is a **high-fidelity product demo** built for the Y Combinator
pitch — a polished, production-*looking* Next.js app running entirely on realistic
mock data (no backend required), so it's fast and reliable to demo live.

---

## Quick start (recommended for the demo)

```bash
npm install
npm run build
npm start
```

Then open **http://localhost:3000**.

> Requires Node 18.18+ (built and tested on Node 24). **Use `npm start` (production
> mode) for the pitch** — it serves the fully compiled stylesheet and is faster and
> more reliable than dev mode on Windows.

Hot-reload dev mode (for editing):

```bash
npm run dev
```

> If dev mode ever renders unstyled, stop it, delete the `.next` folder, and run
> `npm run build && npm start`.

## The demo click-path (rehearse this)

1. **Landing page** (`/`) — hero, marketplace logo marquee, features, pricing.
   Toggle dark/light in the top-right. Click **Live demo** or **Start for free**.
2. **Login** (`/login`) — click any sign-in button (demo mode, no real auth) →
   lands in the dashboard.
3. **Dashboard** (`/dashboard`) — drillable KPI cards, revenue chart
   (toggle **Daily / Weekly / Monthly** + **Compare**), marketplace comparison,
   smart insights, marketplace health, top products, tasks, activity feed.
   Press **⌘K / Ctrl-K** to open the command palette.
4. **Products** (`/products`) — searchable/sortable/filterable catalog with column
   toggles, CSV export, bulk actions. Click a row → **product detail** with
   per-marketplace listings, pricing, inventory.
5. **Orders** (`/orders`) — unified multi-channel order inbox with status tabs and
   filters. Click a row → **order detail** with full timeline, items, customer.
6. **Marketplaces** (`/marketplaces`) — connected channels with health/sync, plus
   available integrations. Click a disconnected one (e.g. **Etsy**) → guided
   connect flow → it becomes connected.
7. **AI Assistant** (`/assistant`) — click a suggested prompt (e.g. *"Show products
   with falling sales"*, *"Predict inventory"*, *"Find pricing opportunities"*).
   Answers render inline charts, tables, and action buttons.

## Architecture

```
app/
  page.tsx              Landing (marketing)
  login/                Demo login
  api/
    assistant/          POST → real copilot agent (mock fallback)
    listing/            POST → Gemini listing generator + S3
  (app)/                Authenticated shell (sidebar + topbar + ⌘K palette)
    dashboard/ products/[id] orders/[id] marketplaces/ assistant/
components/
  ui/ app/ marketing/   UI primitives, product primitives, landing sections
lib/
  mock/                 Deterministic, seeded mock data layer (+ demo fallback)
  db/                   CockroachDB pool + query helpers
  ai/                   bedrock.ts (Claude+Titan) · gemini.ts · s3.ts
  agent/                loop.ts · tools.ts · ops.ts · actions.ts · memory.ts · retrieve.ts
  copilot/              labels.ts (print-ready shipping-label sheets)
  config.ts constants.ts format.ts
db/schema.sql           CockroachDB schema (VECTOR + C-SPANN indexes)
scripts/                setup-db · seed · ingest-embeddings (tsx CLIs)
docs/                   ARCHITECTURE.md · SUBMISSION.md
```

All data lives in `lib/mock/` and is generated by a **seeded PRNG**, so numbers are
stable across reloads and SSR/CSR match. The AI Assistant can now run on a **real
agentic backend** (below); with no configuration it transparently falls back to the
seeded mock, so the app always runs.

## Real AI backend — CockroachDB + AWS + Gemini (hackathon build)

The AI Assistant is a real, tool-using agent with a **CockroachDB memory
layer**, executed on **AWS**, with a **Google Gemini** listing generator. Full
design in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md); submission mapping in
[docs/SUBMISSION.md](docs/SUBMISSION.md).

It is a **coworker, not a chat box**: alongside the analytics tools it can accept,
pack, ship and cancel orders, download print-ready shipping labels, export CSVs,
create orders, re-price and restock SKUs, and navigate you anywhere in the OS.
Every write hits CockroachDB *and* updates the live UI, and every action leaves a
receipt you can undo. It reaches you from any screen as a side dock or a
draggable floating window (`Ctrl`/`⌘`+`J`).

- **CockroachDB** — `agent_memory` + `catalog_embeddings` (`VECTOR(1024)`, C-SPANN
  distributed vector index) for memory recall and semantic RAG; plus the
  products/orders/marketplaces tables ([db/schema.sql](db/schema.sql)).
- **Amazon Bedrock** — Claude (reasoning) + Titan Text Embeddings v2 (vectors).
- **Google Gemini** — the deployed listing/marketing generator.
- **Amazon S3** — generated listings + report exports.
- **AWS Amplify Hosting** — deploys the Next.js 15 SSR app.

### Configure & bootstrap

```bash
cp .env.example .env.local        # fill in COCKROACH_DSN, AWS creds, S3_BUCKET, GEMINI_API_KEY
npm install
npm run db:bootstrap              # setup schema → seed from mock → embed into vectors
npm run build && npm start
```

Env is optional: leave `.env.local` empty and the assistant uses the mock. Set
`COCKROACH_DSN` + AWS credentials to activate the live agent. Scripts:

| Script | Does |
|---|---|
| `npm run db:setup` | Apply [db/schema.sql](db/schema.sql) to CockroachDB |
| `npm run db:seed` | Seed products/orders/marketplaces from `lib/mock/` |
| `npm run db:ingest` | Embed catalog + insights into `catalog_embeddings` (Titan) |
| `npm run db:bootstrap` | All three in order |

### Verify the memory layer

After chatting on `/assistant`, query the cluster (via the CockroachDB MCP server,
`ccloud`, or SQL):

```sql
SELECT role, left(content, 60), created_at
FROM agent_memory ORDER BY created_at DESC LIMIT 5;
```

Each turn is persisted with its embedding. Recall is **scoped to the session id**,
which is minted per window: ask a follow-up like "accept them" in the same window
and the copilot resolves it against what was just said; reload, or hit **New chat**,
and it starts clean. See *Memory lifetime* in
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
